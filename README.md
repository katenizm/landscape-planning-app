# Сценарная оценка территории

Статическое веб-приложение для технической апробации метода сценарной оценки территории на сетке 500 × 500 м. Показаны четыре сценария освоения, нормативные ограничения, ландшафтная чувствительность, рекомендуемые режимы, сравнение ячеек, автоматический подбор и воспроизводимый эксперимент A–D.

Территория демонстрационного набора — Байкальское городское поселение. Численные веса, границы нормализации и пороги классов взяты из синтетической демонстрации НИР-2 и не утверждены для практических решений. Приложение не является научной оценкой Байкальска, градостроительным решением или юридическим заключением.

## Быстрый запуск

Приложение не требует сборки и серверной части. Его можно открыть напрямую:

```bash
open web/index.html
```

Для проверки deep links и поведения, близкого к GitHub Pages, удобнее локальный HTTP-сервер:

```bash
python3 -m http.server 8000 -d web
```

Затем открыть `http://localhost:8000/`.

Данные загружаются из `web/data/data.js`, поэтому основной интерфейс работает и по `file://`. На HTTP-сервере доступны обновление URL при выборе сценария, слоя, ячейки и сравнения.

## Что показывает приложение

- Карту 3468 ячеек с четырьмя сценариями и слоями: рекомендуемый режим, нормативный статус, ландшафтная чувствительность, исходный критерий и расхождения сценариев.
- Карточку ячейки: нормативные доли, зоны, исходные критерии, нормализованные значения, вклад в индекс, SI, класс и рекомендуемый режим.
- Сравнение до восьми ячеек и сравнение одной ячейки в четырёх сценариях.
- Подбор всех ячеек с минимальным SI с точностью до шести знаков среди доступных данных; R3, R2 и ячейки без полного набора данных исключаются.
- Дополнительный эксперимент A–D: влияние нормативного фильтра, судьба R2, пересечение топ-10 и конфликты режимов. Для эксперимента по ТЗ используйте шаблон отчёта ниже.
- Раздел метода с формулами, весами, статусами, режимами, синтетической проверкой, источниками и ограничениями.
- Экспорт выбранных ячеек и результатов подбора в CSV.

## Метод в одном экране

Нормативная проверка выполняется до ландшафтного расчёта:

1. Определяется итоговый нормативный статус ячейки.
2. Запрещённые и непроверенные ячейки исключаются из расчёта чувствительности.
3. Для нормативно допустимых ячеек рассчитываются четыре критерия.
4. Критерии нормализуются, умножаются на веса и суммируются в индекс SI.
5. По порогам 0,25 / 0,50 / 0,75 назначается класс чувствительности.
6. Нормативный статус и класс совмещаются в рекомендуемый режим.

Нормативная проверка не является весом и не компенсируется низким индексом. Для R3 индекс и рекомендация скрыты. Для R2 индекс не рассчитывается до завершения нормативной проверки.

Критерии:

| Критерий | Показатель | Нормализация |
|---|---|---|
| K1 | Крутизна, ° | `z1 = K1 / 20` |
| K2 | Расстояние до гидрографии, м | `z2 = 1 − K2 / 1000` |
| K3 | Доля природного покрова | `z3 = K3` |
| K4 | Расстояние до застройки, м | `z4 = K4 / 1000`; для промышленного — `1 − K4 / 1000` |

Сумма весов в демонстрационных наборах: 1,0 для жилищного и транспортного, 0,999 для промышленного, 1,001 для рекреационного. Значения не перенормируются, чтобы совпадать с сохранёнными результатами ver1.

## Пересборка данных

Исходные результаты НИР находятся вне этого репозитория. Скрипт читает их, проверяет повторяемость расчёта и записывает `web/data/data.json`, `web/data/data.js` и `web/data/experiment.csv`:

```bash
python3 tools/prepare_web_data.py --source "../../НИР/vs code/ver1"
```

Скрипт использует только стандартную библиотеку Python. Исходные файлы не изменяются. Если синтетический CSV недоступен, приложение всё равно собирается, а раздел синтетической проверки показывает пустое состояние.

## Проверки

```bash
python3 -m unittest discover -s tests -v
node --check web/app.js
```

Или через Makefile:

```bash
make test
make check
```

Тесты проверяют нормализацию, пороги, совмещение режимов, приоритет нормативных статусов, целостность `data.json`, статистику сценариев, эксперимент, границу и разбор GeoPackage. Тесты не требуют `pytest`, `pandas`, `geopandas` или других внешних пакетов.

## Данные

Основной набор: `housing_trial_v2`, `industrial_trial`, `recreation_tourism_trial`, `transport_infrastructure_trial`. Используется `housing_trial_v2`, потому что на неё ссылается `scenario_comparison.csv`.

- 3468 ячеек, 94 строки × 73 столбца, шаг 500 м.
- Рабочая система координат EPSG:32648.
- Площадь территории 822,065118 км².
- 362 граничные ячейки.
- 78 нормативных зон; в данных 312 сценарных ключей зон.
- 3423 ячейки с полным набором физических критериев; 34 ячейки R2 и 11 ячеек без полного набора.

Источники: OpenStreetMap / Overpass API (гидрография, здания, граница; ODbL 1.0), ESA WorldCover 2021 v200 (CC-BY-4.0), НСПД ЗОУИТ (первичный скрининг, не юридическое заключение), DEM из технической апробации (источник требует сверки). Подробности — в [docs/data-sources.md](docs/data-sources.md).

## Ограничения

Ключевые ограничения:

- Параметры индекса демонстрационные и не утверждены.
- `no_known_restrictions` не равно юридическому `allowed`.
- Ячейка исключается при любой положительной доле запрета, а не только при полном запрете.
- Доли нормативных зон могут перекрываться и не обязаны суммироваться в 100%; в 116 сценарных записях сумма долей больше 1.
- R2 не имеет диагностического индекса, потому что физические критерии для этих ячеек не рассчитаны ни в одном сценарии.
- Граница OSM может не совпадать с официальной.
- Приложение показывает снимок данных, а не live-подключение к НСПД или OSM.

Полный список — в [docs/limitations.md](docs/limitations.md).

## Эксперимент по ТЗ

1. Выберите вручную ячейку для жилищного сценария, запишите её ID и основание выбора. Повторите для рекреационного сценария.
2. Для каждого сценария запустите поиск без дополнительных фильтров и сравните найденные минимумы с ручным выбором. Обратите внимание на число исключённых и пропущенных ячеек.
3. Выберите одну ячейку и изучите её в таблице сравнения четырёх сценариев. При необходимости экспортируйте таблицы в CSV.
4. Заполните [шаблон отчёта](docs/experiment-template.md). Встроенный дополнительный эксперимент A–D использует другие определения вариантов.

## Публикация на GitHub Pages

Публикация выполняется статически из каталога `web/`. Workflow `.github/workflows/pages.yml` загружает `web/` как артефакт GitHub Pages. Все пути внутри приложения относительные, поэтому сайт работает в подпути репозитория.

Перед публикацией проверьте право публичного распространения данных, особенно нормативного слоя и DEM. Затем:

1. Создайте новый репозиторий на GitHub и в папке проекта выполните `git init`, `git add .`, `git commit -m "Initial commit"`.
2. Добавьте адрес своего репозитория через `git remote add origin АДРЕС` и отправьте ветку `main`: `git branch -M main`, затем `git push -u origin main`.
3. В настройках репозитория откройте **Settings → Pages**, выберите источник **GitHub Actions** и дождитесь завершения workflow во вкладке Actions.
4. Откройте адрес, указанный в настройках Pages, обычно `https://ИМЯ-ПОЛЬЗОВАТЕЛЯ.github.io/ИМЯ-РЕПОЗИТОРИЯ/`. Сборка Python не нужна: готовые данные уже находятся в `web/`.

Работа в браузере и в подпути Pages в текущей среде не проверена: браузер и запуск локального HTTP-сервера недоступны.
