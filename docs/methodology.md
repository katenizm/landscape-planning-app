# Метод

## Назначение

Приложение воспроизводит техническую апробацию сценарной оценки территории: для каждого из четырёх сценариев проверяет нормативную допустимость ячейки, рассчитывает относительную ландшафтную чувствительность и совмещает оба результата в рекомендуемый режим.

Метод демонстрационный. Веса, границы нормализации и пороги классов взяты из синтетической демонстрации НИР-2 и не утверждены для Байкальска. Нормативные сведения — первичный скрининг, а не юридическое заключение.

## Порядок расчёта

1. Выбрать сценарий: жилищный, производственный, рекреационно-туристический или транспортно-инфраструктурный.
2. Проверить нормативный статус ячейки по правилам сценария.
3. Исключить запрещённые и непроверенные ячейки из ландшафтного расчёта.
4. Рассчитать четыре физических критерия для нормативно допустимых ячеек.
5. Нормализовать критерии и получить индекс SI.
6. Назначить класс чувствительности по порогам.
7. Совместить нормативный статус и класс в рекомендуемый режим.

Нормативная проверка не является слагаемым индекса. Запрет нельзя компенсировать низкой чувствительностью.

## Критерии и нормализация

| Код | Критерий | Единица | Границы | Нормализация |
|---|---|---|---|---|
| K1 | Крутизна поверхности | ° | 0–20 | `z1 = clamp(K1 / 20)` |
| K2 | Удалённость от гидрографии | м | 0–1000 | `z2 = clamp(1 − K2 / 1000)` |
| K3 | Доля природного и полуприродного покрова | доля | 0–1 | `z3 = clamp(K3)` |
| K4 | Расстояние до существующей застройки | м | 0–1000 | `z4 = clamp(K4 / 1000)`; для промышленного `z4 = clamp(1 − K4 / 1000)` |

`clamp` ограничивает значение диапазоном `[0; 1]`. Направление K4 зависит от сценария: для производственного освоения близость застройки повышает чувствительность, для остальных — понижает.

Индекс:

```text
SI = w1·z1 + w2·z2 + w3·z3 + w4·z4
```

Веса:

| Сценарий | K1 | K2 | K3 | K4 | Сумма |
|---|---:|---:|---:|---:|---:|
| Жилищный | 0,164 | 0,108 | 0,256 | 0,472 | 1,0 |
| Производственный | 0,277 | 0,160 | 0,467 | 0,095 | 0,999 |
| Рекреационно-туристический | 0,182 | 0,364 | 0,364 | 0,091 | 1,001 |
| Транспортно-инфраструктурный | 0,351 | 0,189 | 0,351 | 0,109 | 1,0 |

Суммы 0,999 и 1,001 — следствие округления демонстрационных весов. Они не перенормируются, чтобы пересчёт совпадал с сохранёнными результатами ver1.

## Классы чувствительности

Используется правило ver1 с включительными верхними границами:

| Условие | Класс |
|---|---|
| `SI ≤ 0,25` | Интенсивное освоение |
| `0,25 < SI ≤ 0,50` | Экстенсивное освоение |
| `0,50 < SI ≤ 0,75` | Ограниченное освоение |
| `SI > 0,75` | Сохранение |

Синтетический пример в исходном CSV использует строгие `<` на точных границах. Приложение следует ver1: значения ровно 0,25; 0,50 и 0,75 попадают в нижний класс.

## Нормативные статусы

| Статус | Смысл |
|---|---|
| `no_known_restrictions` | В полном реестре ограничений зона не найдена; это не юридическое разрешение |
| `conditional` | Использование возможно при условиях нормативной зоны |
| `unclassified` | Есть неопределённая нормативная доля; требуется проверка |
| `prohibited` | Есть запрещающая нормативная доля |
| `not_assessed` | Нормативная оценка отсутствует |
| `allowed` | Подтверждённая допустимость; в текущем наборе не встречается |

Итоговый статус определяется по приоритету:

```text
prohibited → unclassified → not_assessed → наиболее строгий известный статус
```

В ver1 любая положительная доля запрета исключает ячейку целиком. Это консервативное правило реализации, а не универсальная нормативная логика.

## Совмещение статуса и класса

| Нормативный статус | Правило |
|---|---|
| `allowed`, `no_known_restrictions` | Сохраняется класс чувствительности |
| `conditional` | Класс понижается до ограниченного освоения; сохранение остаётся сохранением |
| `prohibited` | Сценарий исключён; индекс и рекомендация не показываются |
| `unclassified` | Требуется нормативная проверка; индекс не рассчитывается |
| `not_assessed` | Нет нормативной оценки; расчёт не выполняется |

Для R3 (запрет) и R2 (неопределённость) ландшафтный индекс не используется как рекомендация. В синтетическом CSV для R3 сохранён диагностический LS; в основном интерфейсе он скрыт.

## Физический банк критериев

В сохранённых результатах ver1 физические критерии заполнены только для ячеек, где ландшафтный этап был разрешён. Для R3 и R2 значения пустые. Чтобы показать физические значения в карточке, приложение собирает их из сценариев, где они рассчитаны.

Это не подмена официального расчёта:

- для каждого сценария отдельно хранится, были ли у него собственные показатели (`own`);
- сохраняется официальный SI только для рассчитанных ячеек;
- диагностический SI не выдаётся за официальный;
- значения критериев проверяются на совпадение между сценариями;
- если полного набора нет, ячейка получает `landscape_status = not_available` или `partial`.

R2-ячейки (34) не имеют физических критериев ни в одном сценарии. Поэтому диагностический SI для них недоступен, и они не ранжируются.

## Проверка воспроизводимости

`tools/prepare_web_data.py` пересчитывает нормализацию, SI, класс, режим и итоговый статус для всех 3468 × 4 записей и сравнивает с сохранёнными значениями. Расхождение хотя бы в одном значении останавливает сборку.

Синтетический пример A–E проверяет формулы на эталонных значениях. Для ячейки D (R3) сохранённый индекс показывается как диагностический.

## Ограничения метода

- Параметры не утверждены.
- Нормативный слой трактуется как полный реестр; `no_known_restrictions` не равно `allowed`.
- Доли зон могут перекрываться и не суммироваться в 100%.
- Граница OSM может не совпадать с официальной.
- Данные OSM и WorldCover имеют ограничения полноты и разрешения.
- Результат не заменяет утверждённый метод, юридическую проверку и полевые данные.
